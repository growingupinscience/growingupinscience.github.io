## Growing Up in Science website

This repository contains the Gatsby site for Growing Up in Science (GUIS).

**Live site:** https://growingupinscience.web.app

`growingupinscience.org` is the canonical public URL; the other hostnames
redirect to it. Domains and TLS certificates are managed in the Firebase
Hosting console — nothing in this repository needs to change when they move.

## Tech stack
- **Framework**: Gatsby 5 (React 18)
- **Styling**: Plain CSS in `src/css`
- **Content**: Markdown via `gatsby-transformer-remark`
- **Hosting/Deploy**: Firebase Hosting

## Project structure

- `src/pages/`
  - `index.js`, `events.js`, `stories.js`, `404.js`
  - `{MarkdownRemark.frontmatter__slug}.js` template renders Markdown content from `src/markdown-pages`
- `src/markdown-pages/`
  - `events/`: Event markdown files (each file becomes a page)
  - `stories/`: Story markdown files
  - `chapters.md`, `participate.md`: Top-level content pages
- `src/components/`: Reusable UI components (e.g., `layout.js`, `menu.js`)
- `src/css/`: Stylesheets (`style.css`, `mobile.css`)
- `src/images/`: Static images and icons
- `public/`: Gatsby build output (generated by `npm run build`)
- `gatsby-config.js`: Gatsby configuration and plugins
- `firebase.json`: Firebase Hosting configuration

## Scripts

```shell
# install dependencies
npm install --force

# start local development server (http://localhost:8000)
npm run develop

# production build into ./public
npm run build

# serve the production build locally
npm run serve

# deploy (builds, then deploys to Firebase Hosting)
npm run deploy
```

## Making a change

1. Branch off `main`.
2. Edit content or components, and check the result with `npm run develop`.
3. Open a pull request against `main`.
4. Merging to `main` deploys automatically — see **Deployment** below.

Because merging publishes immediately, preview your work locally before opening
the PR. `npm run develop` hot-reloads most edits; changes to `gatsby-config.js`
require restarting the dev server, and adding or renaming Markdown files
sometimes needs `npm run clean` to clear Gatsby's cache.

## Content authoring

Most updates are Markdown, not code:

- New stories go in `src/markdown-pages/stories/`.
- New events go in `src/markdown-pages/events/`.
- Standalone pages like `chapters.md` and `participate.md` sit at the top of
  `src/markdown-pages/`.

Each file becomes its own page. Frontmatter must include `slug` and `title`,
plus whatever metadata the template for that content type reads.

The `slug` determines the page's URL, so treat it as permanent once published —
changing it breaks any existing links to that page.

## Common tasks

- **Update browserslist data** (when warned during builds):
  ```shell
  npx update-browserslist-db@latest --yes
  ```
- **Clear a stale build** — if the dev server shows removed content or a new
  Markdown file isn't picked up:
  ```shell
  npm run clean && npm run develop
  ```

## Deployment

Firebase Hosting is the only deploy target. GitHub Pages and the `gh-pages`
branch were retired — do not re-enable them.

- **CI (the normal path):** `.github/workflows/gatsby_deploy.yml` builds and
  deploys on every push to `main`. Nothing manual is required.
- **Manual fallback:** `npm run deploy` builds and pushes straight to Firebase
  from your machine, bypassing CI. Use only if Actions is broken — it publishes
  your local working tree, which may not match `main`.

CI authenticates with repository secrets. If a deploy fails on credentials
rather than on the build, those secrets are the place to look.
